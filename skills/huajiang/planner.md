# 规划者手册

你的产物是一份 `plan.yaml`。它回答一个问题：**这段话讲的是一个什么系统，怎么画成一张连在一起的图。**
你不写坐标、不选字号、不碰 `scenes/`。执行者会照你的计划画；计划里没有的东西，执行者不会替你补。

## 流程

```bash
hj brief <项目>          # 通读口播：逐句时间、停顿、可以直接抄进 at: 的卡点
# 写 <项目>/plan.yaml
hj check <项目>          # 查计划。改到零错误；警告要么修掉，要么准备好向用户说明
hj plan <项目>           # 排出 storyboard.md 和审片页 out/review/plan.png、plan.html（带结构草图）
# 把审片页的图发给用户（SKILL.md 的“交给用户审”），等用户回复确认码
hj approve <项目> plan --by "<用户原话>"
```

用户确认之后，计划就交给执行者了。之后再改 `plan.yaml`，确认自动失效，要重新确认。

## 怎么想：先找系统，再分段

逐句配图做出来的是“带插图的字幕”；一个知识点一页做出来的是“会动的 PPT”。两者的毛病是同一个：没有先找到那张图。

**1. 用一句话说出结论（`thesis`）。** 说不出来，说明还没读懂这段话。

**2. 找出这件事里的“东西”（`cast`）。** 人、机构、钱、货、机器。每个东西定一个固定的长相，全片不变：观众靠它认出“又是它”。
长相只能是画出来的东西（手绘件、小人、图标、图片），不能是一行字或一个方框。抽象的概念找一个能拿在手里的东西代表它：话语权是话筒，风险是炸弹，产能是工厂。
`hj assets doodles`、`hj assets figure` 看有什么现成的；`hj assets sheet --out sheet.png` 把它们画成一张图直接看长相。

**3. 找出东西之间发生了什么（`relations`）。** 谁给谁钱、谁导致谁、谁挡住谁、谁依赖谁。**这是最要紧的一步：关系就是系统的骨架，结论往往就是其中的一两条线。**
把角色当点、关系当边，应该连成一整张网。连不起来的地方，就是你还没想清楚的地方：四个并列的小标题不是系统，要找到它们共同作用在什么东西上。

**4. 决定这张图的形状和分区（`boards`、`grid`）。** 位置本身要有含义：

| 这件事的形状 | 板面怎么分 | 靠什么连 |
|---|---|---|
| 一路推下来（因果、推演、算账） | 从上到下几条横带 | 向下的箭头 |
| 几样东西比长短、比时间 | 几行上下叠放，共用一根轴 | 对齐本身 |
| 两边对照 | 左右两栏，底部一条汇总 | 底部把两栏括起来 |
| 钱、货、信息的流转 | 中间一个圈，四周是注解 | 圈上的箭头 |
| 几股力量作用在一件事上 | 中间是那件事，四周各一股力量 | 都指向中间的箭头 |
| 拆解、分类 | 顶上一个根，往下分层 | 分叉的线 |

这六种形状有现成的版式，写 `layout: 名字` 就不用自己划 `grid`（`hj layouts` 看每种的分区名和比例）：`flow` 一路推下来、`stack` 几行共用一根轴、`compare` 两边对照、`cycle` 转一圈、`hub` 几股力量指向一件事、`tree` 拆开来看。都不合适再自己写 `grid`。

**指定主角（`hero`）。** 这块板讲完后，观众第一眼该看到哪样东西？通常是结论的那个数或那个词。写一条板书的原文（越短越好，不超过 6 个字），或一个角色的 id。执行者会把它画成全板最大、周围留白；别的东西都要让着它。说不出主角是谁，说明结论还没落到一样看得见的东西上。

**5. 把口播分段（`segments`），每段写往图上添什么。** 一段是一个论证动作（设问、说法、理由、例子、算账、数据、对比、转折、推翻、结论、补充），通常 3–15 秒。每一段问三个问题：

- 这句话里的东西是谁？（`show`：让谁出场）
- 它们之间发生了什么？（`link`：画哪条关系；`diagram`：画一个什么图）
- 它和前面讲过的什么有关？（`revisit`：回头改前面画过的谁；`joins`：画一条线连到别的分区）

如果一段话问完只想到“写几个字”，说明还没想透。检查器不接受只有字的段。

**6. 设计“回头”。** 一张连在一起的图最值钱的时刻，是讲到后面回到前面画过的东西上：打叉、改数字、再连一条线。反驳一个说法时，不要另画一张图说“这是错的”，回到表现那个说法的东西上把它划掉。开头立起来的东西，结尾要回来。

## 几块板

**一块板是一张连在一起的图。** 板的数量由内容决定：

- **放得下就一块。** 一两分钟、十来段的内容，一块一屏大的板。
- **一屏放不下，先把板放大**：`size: 1.5`（宽高各 1.5 倍），或 `size: [3, 2]`（三屏宽、两屏高）。全景是缩小的整块板，镜头走近才是原大。大板的分区最好一区正好一屏，按讲的顺序排成一条蛇形的路。
- **确实是几件事，才分成几块板。** 每块至少讲三四十秒。板和板之间必须有共同的东西：同一个角色再出场、一条关系从上一块连过来；或者第一块画一张总图，后面每块写 `recall: 总图的id`，在它上面接着讲。

不要因为“内容多”就一个小标题一块板，那就是翻页。检查器会指出太碎的板和彼此不相干的板。

## plan.yaml 的写法

完整的例子：引擎目录的 `examples/one-board/plan.yaml`。骨架：

```yaml
thesis: 银行把同一笔存款反复借出去，你存的 100 块最多能变成 1000 块存款

cast:                                   # 角色：id 用英文短名；look 只能是画出来的东西
  bank: { name: 银行,   look: { doodle: bank } }
  me:   { name: 你,     look: { figure: stand } }
  shop: { name: 面馆,   look: { doodle: bowl } }
  # 一群：crowd: { name: 储户, look: { crowd: 6, cols: 3, of: { figure: stand } } }

relations:                              # 关系：连两个角色；label 是箭头上的小字（不超过 6 个字，可省）
  dep:  { from: me,   to: bank, label: 存 }
  lend: { from: bank, to: shop }

boards:
  - id: board                           # 英文短名；场景文件会叫 scenes/01-board.yaml
    picture: 每一圈的存款是一条横条，左对齐、逐条变短；借出的钱从右侧绕回来变成下一条；最后往下汇成 1000。
    hero: "= 1000"                      # 主角：讲完后第一眼看到的。板书的原文，或角色的 id
    # layout: stack                     # 可省：现成的版式（hj layouts）。写了它就不写下面的 grid
    # size: 1.5                         # 可省：板比屏幕大
    # recall: 前面某块板的 id           # 可省：板上一开始就有那块板留下的画面
    grid:                               # 板面怎么分：同名的格子连成一个分区（必须是矩形）
      rows: [190, 350, 440, 270]        # 每一行占多高（比例），可省；cols 同理
      areas:
        - [top]
        - [loop]
        - [stair]
        - [bottom]
    regions:                            # 每个分区放什么（给用户和执行者看）
      top: 谁、往哪儿存、规则
      loop: 第一圈
      stair: 后面几圈
      bottom: 汇总
    segments:                           # 按口播顺序
      - at: "假设你存进"                # 这一段从哪几个字开始：从 brief.md 的“分句卡点”里抄
        act: 例子                       # 设问 说法 理由 例子 算账 数据 对比 转折 推翻 结论 补充
        in: top                         # 画在哪个分区
        show: [me]                      # 谁出场（cast 的 id）
        link: [dep]                     # 画哪条关系（relations 的 id）
        words: ["100"]                  # 板书：关键词、数字，每条不超过 10 个字
        intent: 你把钱存进银行；板上出现第一条的数字 100
      - at: "借出去的钱少一成"
        act: 转折
        in: stair
        joins: [loop]                   # 这一段画一条线，把本分区和 loop 连起来
        diagram: 从第二条到第五条，沿着横条的右端拉一条红色斜线     # 要画的图（不是角色的那些）
        words: ["≠ 0"]
        intent: 红色斜线：每条都短一成，但到不了零
      - at: "不只是保管钱"
        act: 结论
        in: top
        revisit: [bank]                 # 回头改前面画过的谁（角色或关系的 id）
        words: [创造存款]
        intent: 回到银行身上：它在创造存款
```

每个字段：

| 字段 | 说明 |
|---|---|
| `thesis` | 一句话的结论 |
| `cast.<id>` | `name` 中文名（会当标签用）；`look` 长相，写法同场景里的元素：`{ doodle: 名字 }`、`{ figure: 姿势, wear: [tophat] }`、`{ icon: 名字 }`、`{ image: 路径 }`，或一群 `{ crowd: N, cols: M, of: {…} }` |
| `relations.<id>` | `from`、`to` 是角色的 id；`label` 可省 |
| `boards[].picture` | 这块板讲完是一张什么图。原样给用户看 |
| `boards[].hero` | 主角：这块板某一段 `words` 里的原文，或在这块板出场的角色 id |
| `boards[].layout` | 版式名（`hj layouts`）。和 `grid` 二选一；分区名由版式定，`regions` 可以不写 |
| `boards[].grid` | `areas` 是几行几列的分区名；`rows`、`cols` 是比例；不放东西的格子写 `.` |
| `segments[].at` | 口播原文片段。从上一段的起点往后找：之后第一次出现就不用加 `#`，要之后的第二次才写 `#2` |
| `segments[].in` | 这一段画在哪个分区 |
| `show` / `link` | 第一次写到某个角色 / 关系的那一段，就是它出场的时刻 |
| `diagram` | 用一句话描述要画的图：横条、时间轴、柱子、走势线、括号、表。写清楚它和前面的图怎么对齐、怎么连 |
| `pattern` | 可省：提示执行者用哪种现成的手法（`hj patterns`：cycle chain versus bars trend timeline thought equation split） |
| `revisit` | 回头改谁。那个角色或关系必须在更早的段里出过场 |
| `joins` | 这一段画一条线连到哪些分区（不是自己所在的分区） |
| `words` | 板书。数字是画面的一等公民；整句话不要写上板 |
| `intent` | 一句人话：这一段画面上发生什么 |

每一段的 `show`、`link`、`diagram`、`revisit`、`joins` 至少要有一样。

## 检查器查什么

| 级别 | 情况 |
|---|---|
| 错误 | 主角不是板上真有的东西；版式名写错；卡点在口播里找不到或顺序不对；角色的长相是字或方框；关系的两头不是角色；有的角色从不出场、有的关系从不画出来；一段只有字；板书超过 10 个字或照抄口播 7 个字以上；回头改一个还没画过的东西 |
| 警告 | 没指定主角，或主角超过 6 个字；角色没连成一张网；分区之间没有任何连线（孤岛）；一块讲了 45 秒以上的板一次都不回头；一段讲 25 秒以上只安排一件事；板分得太碎（不到 30 秒）；几块板之间没有共同的东西；一段的板书超过四处 |

警告指向的几乎都是“系统化”的问题。**修掉它们靠的是把内容想得更清楚，而不是凑一条线。**
确实不适用的（比如这条片子本来就只有一个角色），在把分镜计划交给用户时说明。

## 交给用户时

按 SKILL.md 的“交给用户审”把审片页的图发给用户（`out/review/plan.png` 或 `plan.html`：结构草图加分段表），并用两三句话说：结论是什么；这张图是什么形状、为什么这样分；主角是谁；最关键的那一两条连线或那一次回头是什么。还有没处理的警告就如实列出来。

结构草图只画得出分区、角色、关系和主角；横条、图表这些 `diagram` 在草图上只有一行说明，要在话里讲清楚。

## 给配音方的稿子建议

稿子还能改时，这些会让它好画得多：

- 一句话只讲一件事；先说东西，再说它怎么了。
- 数字说整、说具体（“五十三块”比“一半多一点”好画）。
- 用空行分段，一段讲完整的一件事（10–30 秒）；段和段之间有因果、对比或汇总的关系，而不是并列的几条要点。
