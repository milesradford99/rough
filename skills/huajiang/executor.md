# 执行者手册

你拿到的是一份用户确认过的 `plan.yaml`。你的工作是照它把每块板画出来：每样东西放哪儿、多大、什么时候怎么画。
画什么、分几块板、怎么分区、写哪些字，都已经定了，不归你改。

## 流程

```bash
hj status <项目>                  # 确认现在轮到执行者
hj scaffold <项目>                # 照计划生成骨架：scenes/01-<板>.yaml（每块板一个文件）
# 改场景文件。每改一轮：
hj layout <项目>                  # 每样东西落在哪儿、哪儿空哪儿挤（线框图，在 out/layout/）
hj check <项目>                   # 改到零错误；警告尽量修掉
hj stills <项目> --draft          # 草稿关键帧（out/draft/，带水印）：逐张打开看，改到满意
# 满意之后，分两步交给用户（怎么交见 SKILL.md 的“交给用户审”）：
hj look <项目>                    # 全景定稿：每块板讲完时的全景 → 把 out/review/look.png 发给用户，等确认码
hj approve <项目> look --by "<用户原话>"
hj stills <项目>                  # 逐拍的关键帧 → 把 out/review/keyframes.png 发给用户，等确认码
hj approve <项目> keyframes --by "<用户原话>"
hj render <项目> --draft          # 半分辨率，先看动起来的样子
hj render <项目>                  # 成片 out/video.mp4
```

草稿关键帧是给你自己看的，不能拿去请用户确认。

全景定稿先确认“这张图好不好看、主次对不对”，关键帧再确认“每一拍画得对不对”。先把全景做对：位置、大小、主次定了再细抠每一拍的动作，返工最少。全景定稿确认之后，微调位置不用重来；增删东西、换分区、换大小的档位，要重新确认。

`hj status` 说“轮到规划者”时，说明计划还没有得到用户确认（或确认后又改过）：不要开工，告诉用户。

## 骨架里有什么，你要补什么

`hj scaffold` 生成的文件已经能通过编译：计划里的角色、关系、板书都列成了元素，每一段都有一拍。它缺的是三样，都要你补：

1. **位置和大小。** 骨架里的东西都还堆在分区中间。
2. **每一拍的动作。** 骨架只会 `draw`。滑过去、换表情、打叉、镜头，要你写。
3. **标了“要你画的图”的地方。** 计划的 `diagram` 是一句话的描述（“一条 100 的横条，左端涂红”），要你用形状、数轴、区间条、图表或现成的手法画出来。

骨架的样子（完整的成品见引擎目录 `examples/one-board/scenes/01-board.yaml`）：

```yaml
elements:
  bank: { cast: bank, in: top }                  # 角色：长相来自计划，你只加位置、大小、姿势
  me:   { cast: me, in: top }
  dep:  { arrow: [me, bank], label: "存" }       # 关系：元素的名字就是关系的 id，不能改
  w1:   { text: "100", size: 56, in: top }       # 计划里的板书
beats:
  - at: "假设你存进"                             # 一段的起点：at 不能改、不能删
    intent: "你把钱存进银行"
    do:
      - draw: [me, dep, w1]
```

## 不能做的事（`hj check` 会报错）

- 不能在场景里写 `from`、`regions`、`board`、`recall`：它们由计划决定。
- 不能增删角色。手绘件、小人、图标、图片都必须写成 `{ cast: 角色名, … }`。
- 画关系的那个元素必须叫关系的 id，并且在计划指定的那一段画出来。
- 每一段的起点必须有一拍卡在计划给的那一刻。骨架已经把 `at` 写好了（同一个词在这块板里出现过几次，骨架会自动写成 `#2`、`#3`），不要改、不要删。段内可以再加拍。
- 角色要在计划指定的那一段出场，不能早也不能晚。
- 计划写了 `revisit` 的段，必须有动作落在那样东西身上：给它画标记（`mark`）或批注（`note`）、换姿势表情、移动它、从它再连一条线。在旁边写一个字不算。
- 计划写了 `joins` 的段，必须在这一段的节拍里画（`draw`）一条同时碰到两个分区的线。只定义不画不算。
- 不能加计划之外超过 4 个字的板书。不超过 4 个字的小标签可以加，但别加成字堆。
- 每一段都要画东西，不能只写字。

觉得计划不对（分区放不下、缺一个角色、某一段没法画），**停下来告诉规划者或用户**，说清楚卡在哪一段、为什么。不要改 `plan.yaml`，不要绕过去。

## 怎么摆：不会出错的写法

**坐标只给骨架，其余的相对它摆。** 一块板里手写的绝对坐标超过六七个，说明该换写法了。

| 要做的事 | 这样写 |
|---|---|
| 放进一个分区 | `in: 分区名`，之后 `at: [x, y]` 相对这个分区的左上角；也可以写百分比 `at: ["30%", "50%"]` |
| 挨着另一样东西 | `rightOf: a` / `leftOf` / `above` / `below`，`gap: 30` 调间距 |
| 和前面的东西对齐 | `at: [a.left, 440], anchor: left`：x 取 a 的左边，共用一根轴 |
| 长短、时间、比例 | 一根数轴 `{ axis: [0, 100], length: 500, at: [250, 250] }`（不 draw 它就只当比例尺）加区间条 `{ span: [0, 10], on: 数轴名, at: [0, 250] }`。**不要自己算像素** |
| 一排一样的东西 | `{ crowd: 10, cols: 5, of: { cast: worker }, at: [x, y] }`；一排圆点、方块：`of: { shape: circle, w: 44, h: 44, fill: blue }` |
| 给东西加一行小字 | `label: 小字`（写在正下方），或批注 `{ note: 小字, target: a, side: right }` |
| 圈、叉、划线 | `{ mark: circle, target: a }`，可选 `circle box underline strike cross highlight check`。叉和划线打在箭头上时，只在箭头中间画一个小的（把这条线掐断） |
| 人站在东西上 | `at: boat.deck, anchor: bottom`（手绘件自己声明的锚点） |
| 手里拿东西 | `carry: { doodle: moneybag }` |
| 拿不准位置 | 只写 `near: 某元素`（放在离它最近的空地），或什么位置都不写（引擎从上到下找空位）。不写比乱写好 |
| 微调 | `dx`、`dy` |

引擎会兜底：东西压到别的东西会被自动挪开，出了板会被拉回来，连线会绕路。但“被挪了很远”说明你给的位置本来就不成立，`hj check` 会提示，要回去改。

竖屏画板 960×1250，横屏 1700×800，原点在左上角。画板已经避开了平台按钮和字幕区。板比屏幕大时（计划里的 `size`），画板也跟着变大，骨架开头的注释里写着这块板的实际大小和每个分区的坐标。

## 大小、字号、颜色：照着做就不难看

**大小写档位，不写数字。** 同一档的东西全片一样大，层级就出来了：

| `size:` | 给谁 | 实际大小 |
|---|---|---|
| `hero` | 主角：计划指定的那一样（骨架已经标好）。一块板一处 | 字号 108 |
| `key` | 每个分区的关键数字、关键词 | 字号 64 |
| `label` | 标签、小账 | 字号 46 |
| `note` | 批注、次要的小字 | 字号 40 |
| `big` / `mid` / `small` | 手绘件、小人、图标：主角 / 一般 / 一群里的每一个 | 210 / 160 / 120 |

**主角要显出来。** 别的字不要超过 `key`；主角周围留出半个字高的空，不要让东西贴着围住它。看 `hj stills --draft` 出的眯眼图（`squint-*.png`）：字都糊掉以后，最显眼的那一团应该就是主角。

大板（比屏幕大的板）上每个分区加一个带编号的大标题（字号 100 以上），全景才看得清结构。

**颜色。** 墨色是默认。红色只给三种东西：否定（叉、划掉）、警示的数字、全片的答案；一块板上红字不超过三四处。蓝色给数字、名字和“正面的那一方”。灰色给次要信息。一个概念全片一个颜色。

**对齐和留边。** 并排的东西底边对齐，成行的文字左对齐；所有东西离板沿至少 16。手写的坐标离旁边同类东西的边只差十几个像素时，引擎会吸过去对齐（`snap: false` 关掉）；要可靠地对齐，还是写 `at: [前一个.left, y], anchor: left`。

**三层都要有。** 一块板讲完时应该有：主体（角色和它们的关系）、支撑（数字、横条、柱子、小账）、批注（箭头上的小字、出处、年份）。`hj check` 开头会列出每块板三层各有几样。箭头尽量写上小字：箭头只说“有关系”，小字说“什么关系”。

## 怎么动：让它像一个人在画

**说到什么，手才画什么。**

- 名词出现，东西落笔；动词出现，动作发生；数字出现，数字写下；转折词出现，叉落下来。
- 一拍只做一件事（大约半句到一句话，1–2.5 秒）。一段里有三样东西，就拆成三拍，每拍卡在提到它的那几个字上。`hj brief` 的“分句卡点”表里有现成的片段可以抄。
- 一群人不要一拍闪出来，分两三拍画。
- 要擦掉、划掉的东西，画完至少让它完整地待 1 秒。
- 最后一笔要在配音最后一个字之前落定。

**动作不只有画。** 常用的：

| 动作 | 写法 |
|---|---|
| 画 | `draw: a` 或 `draw: [a, b]` |
| 滑过去 | `{ move: bill, to: gov }`、`{ move: bill, along: 某条箭头 }` |
| 小人走过去 | `{ walk: me, to: boat.deck }` |
| 换姿势、换表情 | `{ pose: me, to: shrug, face: worried }`、`{ face: me, to: surprised }` |
| 就地画一个标记 | `draw: { mark: cross, target: a }` |
| 擦掉 | `erase: a`（只在“推翻前面的说法”时用） |
| 强调一下 | `pulse: a`、`shake: a`、`nod: 小人` |
| 镜头 | `{ camera: { focus: [a, b], pad: 80 } }` 推近；`{ camera: home }` 回全景 |

**小人是讲述者的替身。** 反常的事让它吃惊，坏消息让它垮下来，结论让它摊手或欢呼。换姿势和表情几乎不花时间，是填补“画面静止”最便宜的办法。姿势、表情、配饰的清单：`hj assets figure`。

**镜头可以不写。** 引擎会自己跟着笔走：推近正在画的东西，连线时拉开，结尾回全景。先不写，看草稿；只在想要特别的景别时自己写那一拍（回头改前面的东西时对准它；结论落下前先拉到全景）。看草稿时留意近景有没有把字切在画面边上：切到了就自己写那一拍的镜头，把被切的东西加进 `focus`，或把 `pad` 调大。

**现成的表现手法。** 计划的某一段提示了 `pattern`，或者你看出它是下面这些形状时，用手法比从零摆省事：`cycle` 循环流转、`chain` 因果链、`versus` 两相对比、`bars` 柱子、`trend` 走势、`timeline` 时间线、`thought` 想法泡泡、`equation` 等式、`split` 怎么分。写 `area: 分区名` 把它放进一个分区。`hj patterns <名字>` 打印参数、步骤和例子。手法里的角色同样要写成 `{ cast: 角色名 }`。

## 交图之前自己看

`hj stills <项目> --draft` 之后，**逐张打开看**（联系表 `sheet-*.png` 看全貌，单张看细节）。问：

1. 关掉声音只看画面，看得出在讲什么吗？
2. 讲到每一处时，正在讲的东西是不是画面里最显眼的？
3. 有没有东西太小、互相压住、贴着边、挤成一团，或者一大片空着？
4. 后画的那一层（圈、叉、批注）压到别人了吗？
5. 被引擎挪过的东西（`hj check` 里的“已自动挪开”），还在它该在的地方吗？
6. 最后一帧是不是一张完整的图：有哪几块、怎么连的、结论在哪，一眼看得出？
7. 挨个指着板上的东西问：把它删掉，观众会少知道什么？答不上来的就删。

改到这七条都过得去，再出全景定稿（`hj look`）交给用户。交的时候如实说明：还有哪些警告没处理、为什么。

## 检查器的警告怎么对付

| 警告 | 别这样 | 这样 |
|---|---|---|
| 画得太赶 | 只加 `dur` | 这一拍是不是塞了两件事？拆开，或用 `lead: 0.4` 提前起笔 |
| 画面静止太久 | 加装饰性的圈和下划线 | 那几秒在说什么？给它一拍：小人换个反应、回头在前面的图上添一笔 |
| 被引擎挪了很远 | 不管它 | 换一个放得下的位置，或改成相对摆放。分区里实在放不下：把这一区的东西画小一点、排紧一点 |
| 超出画板安全区 | 不管它 | 多半是长箭头的小字伸出去了：把箭头的一头往里挪，或用 `curve` 让它往里弯 |
| 分区到最后还空着 | 塞点东西进去 | 这一区该放的那一段是不是画到别处去了？写 `in: 分区名` |
| 信息密度偏低 | 多写几行字 | 给箭头加小字、给数字加一行小账、给关键的东西加批注 |
| 一块板上红字太多 | | 只留答案是红的，其余改回墨色或蓝色 |
| 主角不够显眼 / 被围住 | 把主角再放大 | 把抢眼的那一样降一档（`key` → `label`）；把贴着主角的东西挪开，或排到它的同一侧 |
| 字号太多 | | 全部改成四个档位名 |
| 差一点对齐 | 一个个调 `dx` | 让后一个引用前一个的边：`at: [前一个.left, y], anchor: left`，或 `below: 前一个, align: start` |
| 漂着的字 | 挪近一点了事 | 它在说谁？改成那样东西的 `label`，或 `{ note: 字, target: 那样东西 }` |
| 左重右轻 / 右重左轻 | 往轻的一侧塞装饰 | 把支撑的东西（数字、小账、批注）挪过去，或把整组往中间收 |

字段的完整写法查 [reference.md](reference.md)。
