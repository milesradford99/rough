# 导演手册

你的产物是一份 `story.yaml`（创意简报），需要时还有一份改过的稿子 `script.txt`。
它回答一个问题：**观众会因为哪一刻恍然大悟。** 你不写计划、不画画；你决定这条片子靠什么让人看懂、让人惊叹。

简报排在配音之前：它常常要求改稿子，而配音之后再改稿就要重新花钱。

## 流程

```bash
# 读稿子 script.txt（或用户给的想法），写 <项目>/story.yaml，需要时改 script.txt
hj story <项目>            # 查简报：四句话在不在稿子里、顺序对不对。零错误后生成 story.md
# 把 story.md 和稿子全文一起发给用户，说清楚为了惊叹点稿子改了什么
hj approve <项目> story --by "<用户原话>"
```

之后才是确认朗读稿、配音（voice.md），再交给规划者。

## 怎么想：五个问题，按顺序答

**1. 观众原本相信什么？（`audience`、`myth`）**
惊叹不是“学到新东西”，是“原来我一直想错了”。先找出观众脑子里那个说法：大多数人以为的、听着很对的那一个。
找不到可推翻的，就找可补全的：“你知道 A，但不知道 A 是怎么来的”。`myth` 和 `truth` 各一句话，说不短就是还没想清楚。

**2. 惊叹那一刻，画面上发生了什么变化？（`aha`）**
这是整份简报最要紧的一项。惊叹必须是**观众亲眼看见的一个变化**，不是旁白说出的一句结论：

| 惊叹的样子 | 画面怎么变 | `move` |
|---|---|---|
| 原来这么小 / 这么大 | 一个量在眼前长出来、缩下去，或数字滚到一个吓人的数 | `grow` `change` `count` |
| 原来是同一个东西 | 一样东西走过去，变成另一样 | `become` |
| 原来是它导致的 | 结论那一刻，把来路一条一条点亮 | `trace` |
| 原来一直在转 | 记号沿着一圈关系不停地走 | `flow` |
| 原来里面是这样 | 打开一样东西看它的里面，再合上 | `expand` `collapse` |

`see` 用一句话写那一刻画面怎么变；`say` 是那一刻口播的原文。全片只有一个惊叹点，其余都是为它铺路。

**3. 全片靠哪一个画面被记住？（`motif`）**
母题是贯穿全片的那一个画面比喻：开头出现，中间反复用，结尾回来。观众三天后还记得的就是它。
好的母题是具体的、能画的、能变的：“一条横条，每过一轮短一截”，而不是“金融体系”。
抽象的东西先给一个具体的例子（一家奶茶店、一个人、一百块钱），改一个数让它变，最后才说规律。

**4. 揭晓之前，让观众先猜一下。（`predict`）**
抛一个问题：“你觉得会是多少？”“猜猜是谁？”观众心里有了答案，揭晓时才会被打到。猜完不要隔太久就揭晓。
揭晓那一句前面断一下（句号，或单独成段），配音会停半拍：静默是惊叹之前最便宜的铺垫。

**5. 开头和结尾。（`hook`、`land`）**
- 开头头几秒要让人停下来：一个反常的事实、一个和他有关的问题、一个悬念。不要从“今天我们来讲”开始。
- 结尾回到母题（`callback`）：开头那张图又出现了，但观众现在看懂了。

## 改稿子

稿子是为画面写的。为了惊叹点，你可以而且应该改稿：
- **用“但是 / 所以”串，不用“然后”。** 每一段都要么推翻上一段，要么从上一段推出来。
- **把画面已经说清楚的话删掉。** 画面在演一个量变小，旁白就不用再念一遍数字。
- 补上让观众猜的那个问题、揭晓前的那一句停顿、结尾回到母题的那一句。
- 一句话只讲一件事。长句拆开，配音才有呼吸。

改了稿子，交给用户时要说清楚改了哪儿、为什么。

## 交出去之前自己检查

- 把 `myth` 念给一个不懂的人听：他会点头说“对啊”吗？不会，说明这不是观众真正相信的东西。
- 只看 `aha.see`，不听旁白：能想象出那个画面在动吗？想象不出来，就还是一句话，不是一个画面。
- `motif` 能不能在开头、惊叹、结尾三处都出现？
- 惊叹点在稿子的后半段吗？太早揭晓，后面就没人看了。

`hj story` 会查：四句话都是稿子原文、开头在最前面、落点在最后、先猜后揭晓、`predict` 是一个问句、`move` 是能在画面上“变”的动作；配音之后还会查揭晓前有没有停顿。
