# 返工手册：把修改意见变成几行改动

返工是常态。先判断意见是冲着谁来的：

| 用户说的是 | 谁来改 | 改哪儿 | 要重新确认吗 |
|---|---|---|---|
| 讲的东西不对：缺一个角色、关系画错了、这一段该画别的、板书的词不对、分区不合理、想分成两块板 | 规划者 | `plan.yaml` | 要：重新 `hj plan`、用户确认。之后执行者照新计划改场景（`hj check` 会准确报出哪几段对不上） |
| 画得不好：位置、大小、颜色、太挤、太快、太早太晚、小人太木、镜头 | 执行者 | `scenes/*.yaml` | 计划的确认不受影响。只调位置、大小、颜色、时长不用重新确认关键帧；增删节拍、改某一拍画什么，要重新确认关键帧 |
| 读错字、语速、音色 | 配音 | `script.txt` 或 `hj voice` 的参数 | 付费引擎改了稿子要重新确认稿子 |

`hj status <项目>` 会告诉你改完之后轮到谁、下一步是什么。无论要不要重新确认，改完都要如实告诉用户你动了什么。

## 执行者改画面的流程

1. 找到意见对应的那几拍（`storyboard.md` 按时间列着每一段；`hj layout` 能看到每样东西在哪个分区）。
2. 只改相关的几行，不要重写整块板。位置大多是相对的，卡点是口播原文：动一处，其余自动跟随。
3. `hj check <项目>`。
4. `hj stills <项目> --draft --scene <板>` 看这块板的联系表；或 `hj stills <项目> --at "口播片段"` 看某一刻。
5. `hj render <项目> --scene <板> --draft` 只渲染这一段确认动态效果。
6. 全部改完再 `hj render <项目>` 出全片。

## 意见 → 改哪儿

| 用户说 | 改什么 |
|---|---|
| “这个东西往左一点 / 大一点” | 那个元素的 `dx` / `dy` / `size` |
| “这两个挤在一起了” | 其中一个的 `gap` 或 `dx`/`dy`；靠相对定位挂在它身上的元素会自动跟着走 |
| “颜色太多 / 这个要红的” | 元素的 `color` / `fill` |
| “出来得太早 / 太晚” | 节拍的 `at` 换一个口播片段，或加 `lead` / 在锚点后写 `+0.2` |
| “画得太快，看不清” | 把这一拍拆成两拍；或把元素换成更简单的；或加 `lead` 提前起笔 |
| “这里停太久没东西看” | 在那段口播上加一拍：换姿势、圈重点、推镜头 |
| “这句话没表现出来” | 先看计划里这一段写了什么：计划就没安排，交给规划者；计划有、没画出来，执行者补上 |
| “字太多了” | 执行者自己加的小标签直接删；计划里的板书（`words`）交给规划者删 |
| “这个图看不懂” | 加 `label`；角色的长相不好认，交给规划者换（`plan.yaml` 的 `cast`） |
| “小人没反应，太木” | 在关键句上加 `pose` / `face` 动作 |
| “这段不要了 / 两段合并 / 分成两块板” | 规划者改 `plan.yaml` 的 `segments` 和 `boards`，重新确认 |
| “顺序换一下” | 口播顺序决定画面顺序。先改稿子重新配音，再改分镜 |
| “换成横屏” | `project.yaml` 的 `format`；规划者重排 `grid`（竖屏上下排，横屏左右排）并重新确认；执行者重摆位置，`beats` 基本不用动 |
| “字幕有错字 / 断句不好” | 字幕来自时间表。改 `voice/alignment.json` 里对应字的 `display_text`；断句调 `subtitleMaxChars` |
| “音效太吵” | `project.yaml` 的 `sfxVolume`，或 `sfx: false` |

## 换了配音怎么办

重新 `hj voice`（或把新的 `alignment.json` 和音频覆盖进 `voice/`），然后 `hj check`。

- 稿子没变：所有卡点自动对上新时间，通常只需要处理新出现的“太赶”或“静止太久”警告。
- 稿子改了几个字：`hj check` 会准确报出哪些卡点找不到了。计划里的（`plan.yaml` 的 `at`）由规划者改，改了就要重新确认；场景里段内的拍由执行者改。
