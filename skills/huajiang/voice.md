# 配音

目标：一条连续的音频 `voice/narration.wav`，加一份逐字时间表 `voice/alignment.json`。画面的每一笔都卡在时间表上。

三条路，选一条：

| | 命令 | 花钱 | 需要 |
|---|---|---|---|
| 火山引擎豆包语音（默认，音质好） | `hj voice <项目>` | 付费 | 用户的 API Key；用户确认朗读稿 |
| edge-tts（微软 Edge 朗读接口） | `hj voice <项目> --engine edge` | 免费 | Python 和 `pip install edge-tts`（装了 uv 就不用管）；ffmpeg |
| 用户自己有配音 | `hj init <项目> --voice <目录>` | | `narration.wav` + `alignment.json`，格式见文末 |

用户没说用哪个：先问。用户只想先看看效果，用免费的。

## 朗读稿怎么写

朗读稿是 `<项目>/script.txt`：**要读出来的字，不是屏幕上显示的字。**

- **数字按读法写成汉字。** “2026 年”写“二零二六年”，“53%”写“百分之五十三”，“3.15”写“三点一五”，“1000 万”写“一千万”。直接写阿拉伯数字，平台会把一串数字当成一个词，读法可能不对，时间也不准，卡点没法落在它上面。
- **英文缩写想清楚怎么读。** AI、GDP 这类会被当成一个整体。
- **多音字读错了，换一个同音字**（“重仓”读错就写“仲仓”）。字幕要显示原字的话，配完之后改 `voice/alignment.json` 里那个字的 `display_text`。
- **标点就是停顿。** 逗号停约 0.3 秒，句号、问号停约 0.6 秒。要在句子中间多停一下，用省略号“……”（实测约等于一个句号）。破折号不会多停。
- **用空行分段。** 一段讲完整的一件事。段落之间的停顿最适合换一个地方接着画。
- 一句话尽量在 12–22 个字以内。三十个字以上的长句，重音容易错，也不好画。

`hj voice <项目>` 会把稿子里的阿拉伯数字和英文挑出来提醒。

## 火山引擎（付费）

```bash
hj voice <项目>                              # 第一次运行：列出朗读稿全文、音色、读法问题，然后停下
# 把它列出来的内容给用户看，等用户确认这一版稿子
hj approve <项目> script --by "<用户原话>"
hj voice <项目>                              # 确认之后才真的合成
```

**每次调用都花钱，所以规矩很死：**

- 用户没确认**这一版朗读稿的每一个字**，不合成。给了密钥、说了“继续”、批准了大纲，都不算确认稿子。
- 稿子改一个字，确认失效，要重新确认。
- 同一版稿子、同样的音色和语速，不会配第二次；确实要重配加 `--redo`，并先告诉用户这要再花一次钱。
- 没有自动重试。失败了先看报错和 `voice/runs/<序号>/events.jsonl`，判断是密钥、额度、音色还是网络，告诉用户，再决定要不要重来。

**密钥。** 环境变量 `VOLCENGINE_TTS_API_KEY`。没有配置时，请用户自己在终端里设置：

```bash
export VOLCENGINE_TTS_API_KEY=<API Key>
```

密钥在火山引擎控制台的“豆包语音”里创建，需要开通语音合成大模型。**不要让用户把密钥贴进对话，不要把它写进任何文件、命令行参数或日志。**

**参数。**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--speaker` | `zh_male_kuailexiaodong_uranus_bigtts`（快乐小东 2.0） | 音色 id，必须和官方列表逐字符一致，写错会直接报错。其他常用的：`zh_male_kailangxuezhang_uranus_bigtts` 开朗学长、`zh_male_yuanboxiaoshu_uranus_bigtts` 渊博小叔、`zh_female_zhixingnv_uranus_bigtts` 知性女声、`zh_male_xuanyijieshuo_uranus_bigtts` 悬疑解说 |
| `--rate` | 0 | -50 到 100 的整数，0 原速 |
| `--resource` | `seed-tts-2.0` | 名字里带 `uranus` 的 2.0 音色配它；1.0 音色（`BV…_streaming`）配 `seed-tts-1.0`。配错会报“音色不存在”，容易被误当成密钥问题 |
| `--context` | 无 | 风格指令（如“语速平稳，像纪录片旁白”）。效果没有系统验证过，谨慎用 |

## edge-tts（免费）

```bash
hj voice --voices                            # 列出音色和各自的默认语速、音高
hj voice <项目> --engine edge                # 默认音色：云健
hj voice <项目> --engine edge --speaker zh-CN-YunxiNeural
```

免费，所以不需要用户确认稿子，失败会自动重试几次。它是微软的非官方接口，偶尔会 403 或超时，过一会儿再试。

它只能调语速、音高、音量，不能控制情绪和精确停顿。默认值是实测定的：

| 音色 | 特点 | 默认语速 | 默认音高 | 原速实测 |
|---|---|---|---|---|
| `zh-CN-YunjianNeural` 云健（默认） | 男，厚实、起伏大 | `+4%` | `-4Hz` | 4.07 字/秒 |
| `zh-CN-YunxiNeural` 云希 | 男，年轻、口语感最好 | `+0%` | `-4Hz` | 4.25 |
| `zh-CN-XiaoxiaoNeural` 晓晓 | 女，清亮、吐字最稳 | `+4%` | `-2Hz` | 4.10 |
| `zh-CN-XiaoyiNeural` 晓伊 | 女，低一点、温和 | `+0%` | `-2Hz` | 4.23 |
| `en-US-BrianMultilingualNeural` | 男，多语言模型说中文，松弛的播客腔 | `+16%` | `-3Hz` | 3.59 |
| `en-US-AndrewMultilingualNeural` | 男，多语言模型说中文，胸腔共鸣重 | `+28%` | `-3Hz` | 3.20 |

- **语速按“画得过来”定，不按“听着紧凑”定。** 默认值让成片落在每秒 4.1–4.3 个字。网上常见的建议是提速 10%–16%，那样会到每秒 4.6–4.9 个字，一句话的时间只够画几笔。只有内容本来就画得少时才往上调（`--rate +8%`）。配完之后 `hj voice` 会报实际的每秒字数。
- **音高微降**能去掉一点电子味：男声 -4Hz 左右，女声 -2Hz 左右。超过 ±15Hz 会失真，`hj` 会拒绝。
- **音量不调。** 合成之后统一做一次响度标准化（-16 LUFS）。
- **段落之间自动补足 1 秒停顿。** 稿子按空行分段各合成一次、接成一条音轨，时间表跟着平移。
- 网上推荐的 `zh-CN-XiaoxiaoMultilingualNeural` 在免费接口上已经不可用（实测不返回音频），不要用。`zh-CN-YunyangNeural` 是新闻播报腔，逗号几乎不停顿，不适合讲解。

## 配完之后

- 先让用户听一遍 `voice/narration.wav`。
- **不要再对音频做剪切、变速、去静音、拼接。** 任何改动都会让时间表失效。不满意就改稿子或参数重配。
- `hj brief <项目>` 里带 ~波浪线~ 的字（数字、英文缩写）时间不可靠，卡点别落在它们上面。
- 改稿重配后，画面的卡点是按口播文字绑定的：稿子没改的部分自动对上，`hj check` 会准确报出哪些卡点找不到了。

## 用户自己提供配音

需要一条连续的音频（建议 48 kHz、16-bit、单声道 WAV）和逐字时间表，放在同一个目录里，`hj init <项目> --voice <目录>`。

`alignment.json` 的格式（时间相对于这条音频的开头，单位秒）：

```json
{
  "duration_seconds": 221.05,
  "units": [
    { "text": "你", "display_text": "你", "start": 0.000, "end": 0.155, "confidence": 0.94, "timing_warnings": [] },
    { "text": "信", "display_text": "信，", "start": 0.705, "end": 1.145 }
  ]
}
```

`text` 是一个字（或不可再分的词，如“AI”），不含标点；`display_text` 带上紧跟其后的标点，字幕靠它断句；`confidence` 低于 0.6 或 `timing_warnings` 非空，会被当成“时间不可靠”。只有 SRT 字幕也能做（放 `subtitles.srt`），但只有句级精度。

给配音方的节奏建议：每秒 3.8–4.3 个字；句间停 0.5–0.8 秒，段间停 1.0–1.5 秒；关键数字前轻顿并放慢；设问之后停 0.6–1.0 秒；反转和结论之前停 0.8 秒左右。不要为了凑时长整体变速。
