# 评测集（evals）

一套固定的 12 条口播稿，用来在每次改框架之后跑同一套流程、比同一组数字：
**agent 照 AGENTS.md 给每条稿子写分镜 → 出草稿关键帧 → 打分。** 稿子不变，分数的变化才说明框架变好或变差了。

这不是交付流程。评测里**不经过人工确认，不运行 `hj approve`**，被打分的是 `hj stills --draft` 的输出。

## 用例

每个用例在 `cases/<编号-名字>/`，含 `script.txt`（口播稿，230 到 260 字上下，约 55 秒）和 `case.yaml`（体裁、论证形状、风格参照、一句话要点、3 道选择题）。稿子都是原创，参照的博主只是风格参考。

## 跑一轮

```bash
npm install                                  # 首次
node evals/prepare.mjs                       # 为每个用例建 work/eval-<编号-名字>/
```

`prepare.mjs` 用 `hj fake-align` 按匀速（默认每秒 4.5 字，`--cps` 可改）造时间表，再 `hj init`。可以重复运行；已经有场景文件的项目不会被动。只准备部分用例：`node evals/prepare.mjs 03 07`。竖屏是默认，`--format landscape` 改横屏。要重来某个用例，删掉 `work/eval-…/scenes/` 里的文件再运行。

每个项目分别交给一个 agent（同一轮里模型、提示都一样），提示大致是：

> 项目在 `work/eval-XX-名字/`。按 AGENTS.md 和 docs/directing.md 为它写完整分镜（先填 outline.md 和 cast.yaml）。没有用户，不运行 `hj approve`，不要等确认。`hj check` 清到零错误，警告尽量修掉；`hj stills --draft` 看图，改到满意为止。完成后停下，不要渲染视频。

agent 写完后，在每个项目上：

```bash
npx hj check work/eval-XX-名字 2>&1 | tail -20     # 记错误数、警告数
npx hj stills work/eval-XX-名字 --draft            # 草稿关键帧和联系表
```

注意：`hj stills` 的正式版需要确认过的分镜，评测一律用 `--draft`。草稿的水印不影响打分。

## 打分表

每个用例三项，都记下来：

**(a) 画面，满分 10。** 对象是 `frames.mjs` 取出的两类图：

- **全景终帧**（`<板>-全景.png`），四项各 0 到 2 分，标准见 docs/directing.md 第十三节：看图知意、三层齐全、构图、和口播的对应。
- **连成一张图**（只看全景终帧，0 到 2 分）：0 = 几块互不相干的小图拼在一起；1 = 有分区，但块和块之间没有对齐、连线或回指；2 = 看得出结构，结论是从前面的东西连出来的。
- 中途画面（`<板>-中途N.png`）不单独计分，用来扣分：有一张看不出正在讲什么、或正在讲的东西不是画面里最显眼的，构图一项减 1。

分章的片子每块板各打一次，取平均。评分的人（或模型）可以看口播，要对照检查“和口播的对应”。

**(b) 只看画面能答对几题（满分 3）。** 跑 `node evals/frames.mjs`（可带用例前缀，如 `01 07`）：它为每个写好分镜的用例出一套关掉字幕的草稿关键帧，把每块板的全景终帧、三张中途画面和去掉答案的题目放进 `work/eval-judge/<用例>/`。找一个只看得到这个目录的模型，让它逐张打开这些图、回答 `questions.yaml` 的 3 道题，每题选一个选项，对答案计分。不要给它口播稿。题目考的是意思（谁导致谁、哪个更大、结论是什么），不是字面。

**看图的两条规矩**（第一次试跑踩过的坑）：
- 给评分模型看**单张的原尺寸画面**，不要给联系表。联系表把画面缩到六分之一，批注的字在上面必然读不出，“字太小”会被误报。
- 告诉评分模型：画面最下面约五分之一是留给字幕的（这里关掉了），那里空着不算构图的毛病。

**(c) `hj check` 的错误数和警告数。** 错误数应该是 0；警告数越少越好，记原始数字。

评分前先别看 `case.yaml` 的 `takeaway` 以外的内容，避免用答案去脑补画面。

### 从检索里能确认的结构特点

- 常见口播结构是“问题、反常识、拆解”，开头三秒要立钩子；钩子常见有提问、提醒、“时间加结果”、反常识。
- 文案多用短句，念出来检验语感。
- 快手的半年报转述：超过 60 秒的短视频里，法律、科学、财经类增长最快。
- 其余的结构观察（例子贯穿到底、转折落在中后段、结论一句话）来自写稿人对这些账号的印象，按各体裁写进了稿子，没有逐字对照。

### 实际打开或检索到的页面（域名）

woshipm.com、digitaling.com、cbndata.com、36kr.com、jiemian.com、sspai.com、thepaper.cn、tmtpost.com 等，都只是通过搜索结果摘要看到，没有逐页打开全文。没有访问被代理拦截的站点；没有尝试直接访问抖音、B站。

## 加新用例

在 `cases/` 下建 `<编号>-<名字>/`，放 `script.txt` 和 `case.yaml`，再跑 `prepare.mjs`。稿子要求：口语、有一个钩子、一个带具体数字或场景的例子、一句要点；编造的数字必须说明是举例（“假设”“比如”）。选择题 3 道，4 选 1，考意思不考字面，不看这段就不该靠常识答对。改了旧稿子就等于换了题，结果表里要另起一行说明。
